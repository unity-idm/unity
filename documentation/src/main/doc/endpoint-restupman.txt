[[endp-rest-upman]]
=== RESTful Upman API endpoint

Endpoint type:: +RESTUpman+
Binding:: RESTful
Exposed paths:: +/v1/*+

This endpoint exposes a RESTful API allowing for management of Unity projects, exposed by <<endp-upman>>.
The endpoint requires two configuration properties:

. +Root group+ - under which the projects shall be managed.
. +Authorization group+ - users authenticating directly must be members of this group and have the authorization attribute +sys:ProjectManagementRESTAPIRole+ set in this group.

Example:

----
unity.upman.rest.rootGroup=/A
unity.upman.rest.authorizationGroup=/A
----

Forms created or updated through this endpoint can collect attributes in Unity's root group +/+ only when
the attributes are explicitly allowed. Configure numbered +unity.upman.rest.rootGroupAttributes.N+ entries,
for example +unity.upman.rest.rootGroupAttributes.1=name+ for the +name+ attribute collected by autogenerated
registration forms. The root group +/+ in this setting is distinct from the projects root configured above.
Without this entry, updating an autogenerated form can fail even if its retrieved JSON is unchanged.

OAuth bearer token access requires a bearer token authenticator in the endpoint's authentication flow.
The built-in scope +sys:upman-api+ grants access to all projects, including project creation.
The built-in pattern scope +sys:upman-api:.++ permits a concrete scope such as
+sys:upman-api:project-x+ for access to one project. Project-scoped tokens can list projects,
but the response contains only projects covered by their scopes. For nested projects, the scope
suffix is the project path relative to the configured root, such as +project-x/child+.

The documentation of the REST API is available on a separate page
link:upman-rest-api-v1.html[REST API]
