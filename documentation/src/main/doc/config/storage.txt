[[db-conf]]
=== Storage configuration

Unity currently supports Relational Database Management System (RDBMS) as backend storage.

The database configuration is provided in the main +unityServer.conf+ file.

Note that addition to database backup the Admin Console provides a possibility to create a JSON dump of the complete server state, and to restore the system from such dump.

 
==== RDBMS storage backend

The following databases are supported: 

. H2 (embedded, no setup required)
. MySQL
. MariaDB
. PostgreSQL

RDBMS service is stable, quite fast and offers an excellent ecosystem of maintenance supporting tools (backups, redundancy, etc) which is available for the mature RDBMS technology.

The following table enumerates all configuration options for the RDBMS backend. 

include::../ref-storeRDBMSProperties.txt[]

The remaining part provides more insight into specific setup of databases used by Unity. Note that if the simple 
embedded H2 database is used no special setup is required - it works out of the box. However is not recommended
for production use as handling backups and redundancy is very problematic with it.


===== MySQL and MariaDB database preparation

For either database, create a database and a separate user. In the database command-line client, logged in
with administrative privileges, execute:

----
CREATE DATABASE unitydb;
CREATE USER 'unity'@'localhost' IDENTIFIED BY 'unitypass';
GRANT ALTER, CREATE, DELETE, DROP, EXECUTE, INDEX, INSERT, LOCK TABLES,
   SELECT, TRIGGER, UPDATE, REFERENCES, CREATE ROUTINE ON unitydb.* TO 'unity'@'localhost';
----

Replace the database name, username and password with your values. If Unity runs on another host, replace
+localhost+ in the user account and grant with that host. Test the credentials with:

----
mysql -p -u unity unitydb
----

For MariaDB, the +mariadb+ command-line client can be used instead. Unity creates its tables on startup.

Both databases use the following Unity settings:

----
unityServer.storage.engine=rdbms
unityServer.storage.engine.rdbms.dialect=mysql
unityServer.storage.engine.rdbms.username=unity
unityServer.storage.engine.rdbms.password=unitypass
----

Add the JDBC URI described in the appropriate section below. The URI scheme selects the driver; connection
options and their defaults belong to that driver.

[[mysql-storage]]
===== MySQL connection

Use MySQL Connector/J with a +jdbc:mysql:+ URI:

----
unityServer.storage.engine.rdbms.jdbcUrl=jdbc:mysql://localhost/unitydb
----

MySQL Connector/J accepts the following +sslMode+ values:

[cols="1,4",options="header"]
|===
|Value |Behavior

|+DISABLED+
|Connects without TLS. Traffic is unencrypted.

|+PREFERRED+ (default)
|Uses TLS when the server supports it, without verifying its certificate or hostname. Falls back to an
unencrypted connection when TLS is unavailable.

|+REQUIRED+
|Requires TLS, but does not verify the server certificate or hostname.

|+VERIFY_CA+
|Requires TLS and verifies that the server certificate is trusted, but does not verify the hostname.

|+VERIFY_IDENTITY+
|Requires TLS and verifies both trust in the server certificate and that it matches the hostname in the JDBC URI.
|===

For example, append +?sslMode=VERIFY_IDENTITY+ to the JDBC URI to require a verified TLS connection.
Configure the JVM trust store or MySQL Connector/J's +trustCertificateKeyStoreUrl+ option when using a private
certificate authority.

Some authentication methods on connections without TLS require the server's public key. Configure
+serverRSAPublicKeyFile+ rather than enabling +allowPublicKeyRetrieval=true+ over an untrusted network, where
an attacker could substitute the key.

See the https://dev.mysql.com/doc/connector-j/en/connector-j-connp-props-security.html[MySQL Connector/J security
options] for details. These option names and defaults apply to the MySQL driver.

[[mariadb-storage]]
===== MariaDB connection

Use MariaDB Connector/J with a +jdbc:mariadb:+ URI. Keep Unity's +dialect+ set to +mysql+ as shown in the
shared setup above:

----
unityServer.storage.engine.rdbms.jdbcUrl=jdbc:mariadb://localhost/unitydb
----

[[mariadb-ssl-mode]]
====== MariaDB TLS modes

MariaDB Connector/J 4 accepts the following +sslMode+ values:

[cols="1,4",options="header"]
|===
|Value |Behavior

|+disable+
|Connects without TLS. Traffic is unencrypted.

|+trust+
|Requires TLS, but does not verify the server certificate or hostname. Intended for development only.

|+verify-ca+
|Requires TLS and verifies that the server certificate is trusted, but does not verify the hostname.

|+verify-full+ (default)
|Requires TLS and verifies both trust in the server certificate and that it matches the hostname in the JDBC URI.

|+allow+
|Uses +verify-full+ when the server announces TLS support; otherwise connects without encryption. This is a
migration mode for a mixture of servers with and without TLS. The server announces its capabilities before
TLS is established, so an active attacker can force an unencrypted connection. Use +verify-full+ once all
servers support TLS.
|===

Values are case-insensitive. The driver also accepts the aliases +DISABLED+, +0+ and +false+ for +disable+;
+REQUIRED+ for +trust+; +VERIFY_CA+ for +verify-ca+; and +VERIFY_FULL+, +VERIFY_IDENTITY+, +1+ and +true+ for
+verify-full+. Prefer the canonical values listed in the table when writing new configuration.

For example, explicitly select the default with:

----
unityServer.storage.engine.rdbms.jdbcUrl=jdbc:mariadb://localhost/unitydb?sslMode=verify-full
----

The database server must support TLS, and its certificate must be trusted and match the hostname in the JDBC URI.
Configure the JVM trust store or MariaDB Connector/J's +serverSslCert+ option when using a private certificate
authority. An explicit +sslMode+ in the JDBC URI overrides the default.

For authentication without TLS, MariaDB Connector/J provides +serverRsaPublicKeyFile+ and
+allowPublicKeyRetrieval+; the same public-key retrieval risk described above applies. Note the different
capitalization of MySQL's +serverRSAPublicKeyFile+ option.

See the https://mariadb.com/kb/en/about-mariadb-connector-j/[MariaDB Connector/J documentation] for its
connection options. MySQL Connector/J's +PREFERRED+ mode is not a MariaDB +sslMode+ value.

===== PostgreSQL setup

The setup of PostgreSQL (Unity should be compatible with any recent version) 
requires creation of a database with a separate role (user) 
which is able to connect to the database. Typically on Linux system you have to invoke:

 createuser -P unity
 createdb -O unity unitydb
 
using the desired database name, username and password. Of course any other tool can be used to create the user and
database. Finally note that Postgres must allow for password authentication for the Unity user. Ensure that
in +pg_hba.conf+ you have a lines similar to those two:

 host   all         all         127.0.0.1/32          md5
 host   all         all         ::1/128               md5

If the database is on a different host then the Unity instance, change IP addresses to a proper ones.  

Test if the connection works with:

 psql -h localhost unitydb unity

and give the configured password.

Unity server will setup all tables automatically on startup.

To configure Unity to use the Postgres database change the default database JDBC URI as well as 
add the username, password and dialect:
 
----
unityServer.storage.engine=rdbms
unityServer.storage.engine.rdbms.jdbcUrl=jdbc:postgresql://localhost/unitydb
unityServer.storage.engine.rdbms.dialect=psql
unityServer.storage.engine.rdbms.username=unity
unityServer.storage.engine.rdbms.password=unitypass
----
